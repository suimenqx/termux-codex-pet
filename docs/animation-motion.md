# 动作、时间与流畅度规范

先完成[模型和构图基准](animation-assets.md#角色模型与尺寸)，再填写[制作单](templates/pet-animation-brief.md)里的动作表。本文规定怎样安排姿势、补帧、检查循环和处理状态切换；具体帧数、逻辑映射和时长仍由 [`animation.py`](../codex_pet/animation.py) 管理。

## 动作服务于状态

| 状态 | 动作目标 | 生命周期与审查重点 |
| --- | --- | --- |
| Idle | 安静陪伴，能看出仍然活着 | 呼吸和次要动作循环；身体不会随眨眼跳位，休止是有意节奏 |
| Running | 表示工作进行中 | 连续步态；四肢相位、躯干起伏、尾巴跟随和循环接缝协调 |
| Needs input | 清楚表达需要用户关注 | 可读手势与停留；不能为了播完其他动作而延迟进入此状态 |
| Ready | 表达一次完成反应，随后安静等待 | 进入动作与稳态循环分别设计；周期边界不能再次回到腾空姿势 |
| Blocked | 表达困惑或受阻 | 有限反应后稳定保持；保持姿势本身也应完整表达状态 |

需要改变这些语义或新增过渡时，在制作单中注明用户可见变化和播放层影响。给静止状态增加连续动作、让 Ready 反复跳跃都不是单纯的画面补帧。

## 先安排时间，再补画中间姿势

区分三个概念：独立画稿数、逻辑播放位置数、设备显示刷新率。同一图可以停留或被复用；提高设备刷新率或重复同一张图不会产生新的肢体姿势。流畅度还取决于相邻姿势的空间间距、遮挡变化、受力关系与显示时序。

采用“关键姿势 → 决定运动路径的中间关键姿势 → 中间帧”的顺序。先在时间轴上锁定接触、蹬地、腾空极值、落地、回收和停顿，再补齐这些阶段之间的变化。这种先关键姿势后补充动作的制作顺序可参见 [Toon Boom 的 pose-to-pose、breakdown 定义](https://docs.toonboom.com/help/game-studio-24/game-studio/glossary/gaming-glossary.html)。

每个逻辑位置填写：`pose_id`、源图/合成映射、`t_ms`（开始时间）、`hold_ms`、动作阶段、支撑肢体、可见/遮挡、头胸髋和脚掌的动作目标，以及与下一姿势的连接方式。遮挡点写 `occluded`；不能拿邻近脚掌替代不可见脚掌来通过审计。

时间约束：

```text
t[0] = 0
t[i+1] = t[i] + hold[i]
hold[i] > 0
T = sum(hold[i])                 # 一个循环的时长
N = 一个循环内的逻辑曝光数
平均曝光推进频率 = N / T秒         # 相邻位置可复用同图；不是流畅度合格线
```

以上公式用于有限曝光和循环段。动作结束后的无限保持另写 `final_hold = until_state_change`，不填一个虚构的大时长；离线工具为展示保持而使用的有限停留时间，不是运行时的状态寿命。

旧跑步是 8 个姿势、每个 80 ms，总周期 640 ms。若在每一段中间真正增加一个姿势，并保持原来的关键事件时刻，可以把每段 80 ms 分成 40 ms + 40 ms：得到 16 个姿势、同样的 640 ms，平均切换频率由 12.5 变成 25 次/秒。当前共享骨骼已采样为 32 姿势 × 20 ms，仍为 640 ms。上面的 16 帧是时长守恒的算例，不是要求所有动作都做成 16 帧或 25 fps。新增姿势后仍维持每帧 80 ms 会把周期改成 1280 ms，属于改变步频。

优先在轨迹弯折、关节转向、脚掌接触/离地、遮挡交换或原速明显跳跃处补帧。接触和蓄力的停顿可以有不同曝光时长，不能为了“等帧率”抹掉动作节奏。把远距离关键姿势直接延长播放，只会延长停顿。

## 轨迹与受力

- 头、胸、髋、脚掌和尾根分别跟踪。身体先起伏、尾巴稍后跟随等相位关系写入计划；不把所有部位以同幅度、同方向同时平移。
- 前伸、回收等摆动通过连贯弧线完成。加速/减速表现为相邻姿势的间距变化；落地受力允许明确速度变化，不能用统一平滑曲线消除接触感。
- 呼吸、下蹲和拉伸保留角色体积感；脸部特征、配件与毛色区域随着同一结构运动。高频毛发纹理、明暗或轮廓每帧重新生成造成的闪烁也属于不合格的运动。
- 洋葱皮叠加用于检查轨迹和结构一致性，原速播放用于判断节奏；两者都要保留证据。[Toon Boom：Onion Skin](https://docs.toonboom.com/help/game-studio-24/game-asset-editor/cut-out-animation/use-onion-skin-cut-out-animation.html)
- 相邻帧混合、重复画稿、自动光流可以产生更多图像，但结果仍须满足同一解剖与接触表。出现重影脚掌、关节融化或数量变化时重画该段，不能只用模糊覆盖。

### 原地奔跑的坐标关系

悬浮窗里的宠物只在用户拖动时改变屏幕位置。跑步画稿表现原地循环，运动中的髋部是躯干标记，不能每帧用它把整张图重新居中。

判断滑步须明确坐标系。假设虚拟地面中的角色根位置为 `R(t)`，脚掌相对角色的位置为 `q(t)`，则世界位置 `P(t)=R(t)+q(t)`。支撑期间 `P(t)` 近似不动，因此原地跑姿中的脚掌会相对身体向后运动；回收期离地再前摆。要求支撑脚始终固定在原地跑姿的画布坐标中，会与这一关系冲突。制作单应标明支撑阶段、共同地面基线和计划中的相对移动方向，不能仅按像素变化多少判断在迈步。

### 四足协调

选择实际采用的步态和领腿，保持近/远侧前后肢身份。每个关键事件记录谁支撑、谁蹬地、谁回收，以及身体如何响应；侧视遮挡可以发生，轮廓仍应让整轮的四肢动作可理解。不能为了每帧同时露出四只脚而把腿强行展开。

秋田犬当前骨骼接触相位、32 帧安排和参考研究见[奔跑步态文档](animation-gait.md)。它是已有简化动作，不是所有犬只的固定周期模板。换步态、镜头或帧数后须重新导出接触表、关节与遮挡数据；审计核对哈希后使用这些数据，不能沿用旧坐标判断自然。

## 循环接缝与状态切换

### 循环边界

循环按 `[0,T)` 交付，`T` 时刻回到开头。除非明确设计停顿，不在结尾重复一张已经在开头曝光的同姿势图，否则重复曝光会改变节奏。

把倒数第二帧、末帧、首帧、第二帧一起检查：模型尺度、动作方向、支撑关系和间距须能连续解释。首尾相似只检查了位置；如果运动方向突然反转，循环依然会顿挫。可用相邻标记的 `v[i] ≈ (p[i+1]-p[i])/hold[i]` 作诊断，循环段包含末帧到首帧；接触造成的变化由阶段解释，不设跨动作通用速度阈值。非等时曝光必须使用各自时长。

### 状态边界

当前 `AnimationTimeline.sync()` 会在视觉状态变化时从目标逻辑帧 0 开始；Running 数量徽标变化也会触发重置。动作可能在任意姿势被打断。审查源状态的每个逻辑位置 → 目标首帧，重点检查 Running↔Idle、Running→Needs input、Running→Ready，以及 Ready 进入动作被打断。Blocked 等演示状态也不能漏掉。

跨状态保持模型尺度、构图原点和支撑基准。正侧面切换带来的姿势跳变与缩放错误分别记录；一套正确图片无法单独保证任意相位、任意视角切换都平滑。确需过渡帧或运行时衔接逻辑时明确提为播放层变更，并保证新的会话状态立即生效，动画过渡可被再次打断。

## 播放与性能边界

根据原速预览确定必要的独立姿势数量，再检查设备能否按时显示。若离线动作连续而设备掉帧，检查解码、PNG 传输、GUI 调用与帧截止时间，不继续盲目堆帧。当前时间轴使用单调时钟并跳过过期帧，审查应区分画稿缺失和运行时跳帧。

增加独立帧也增加加载与缓存成本。`C×C×4×N` 字节只估算 N 张 8 bit RGBA 帧的解码像素量；PNG 文件、合成变体、Python 对象和原生缓存另计。记录变化并对照 `art.py` 的实际缓存与设备行为，不把该公式当作进程总内存。

为每个状态保留可读的静态代表姿势，持续循环保持适合工作场景的注意力强度，避免无意的高对比闪烁。将来提供减弱动画模式时可以复用这些姿势；当前项目没有该模式的用户开关，素材规范不代表已经实现这一功能。

当前离线工具按源码播放表输出，浏览器的像素和定时器并不等同于 Android 原生渲染。每次增加帧或缩短间隔记录设备、密度、目标曝光时长和实际观察；不能仅根据预览宣称所有设备达到某个帧率。完整验收方法见[验收与接入](animation-acceptance.md)。
