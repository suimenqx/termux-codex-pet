# 动画素材验收与接入

本文件与[尺寸规范](animation-assets.md)、[动作规范](animation-motion.md)共同构成验收要求。结果写入本次[制作单](templates/pet-animation-brief.md)，每项使用 `pass`、`fail` 或 `pending` 并关联当前版本证据。`不适用`需要说明原因；待测和待看不能填成通过。

## 文件检查

以下是可自动核对的契约，不表示图片本身已经自然或美观。

| 项目 | 要求与检查依据 |
| --- | --- |
| 像素与解码 | 每张生产 PNG 可解码，尺寸符合外观注册，颜色类型/位深符合素材契约；透明区域确有 alpha，不是画上去的背景 |
| 来源 | 参考图、源图、提示词、实际网格、导出命令和文件哈希能对应到本次制作版本 |
| 帧完整性 | 独立图片编号连续、无缺失/旧文件残留；逻辑位置能解析到实际图片或明确的合成结果 |
| 时间表 | 时长为正，累计时刻与计划一致；循环/进入/保持分别核对；补帧保留约定的关键事件时刻与周期 |
| 回退图 | 每个 `<state>.png` 与该状态物理 `frames/<state>/00.png` 逐字节一致 |
| 导出映射 | 画布整体等比映射，未按姿势独立居中或缩放；原始格号、物理编号与逻辑播放位置有对应表 |

这些信息应从源文件和实际播放路径读取。工具返回成功、图片后缀是 `.png`、第一像素透明，都不足以证明没有假透明背景、跨格内容或裁断四肢。

## 模型与动作审查

| 审查 | 方法 | 判定 |
| --- | --- | --- |
| 大小与模型身份 | 同视角模型参照叠加；核对头脸、胸髋结构、毛色和配件；用制作单的标记与单位比较 | 预期姿势/透视/形变以外的比例漂移要修正。不能用跨姿势 alpha 面积替代 |
| 定位与边界 | 固定画布翻帧，叠加构图原点、支撑基线和动作极值；查看四边 | 意外整体位移、裁切、格线或邻格串入为失败。半透明边缘要合成后判断 |
| 帧间连贯 | 查看相邻帧与洋葱皮；追踪躯干、脚掌、尾根、配件 | 检查关节、肢体身份、纹理稳定性和预期轨迹；脚掌遮挡按制作单解释 |
| 原速节奏 | 使用真实曝光时长播放完整进入/循环/保持，循环至少覆盖一次首尾衔接 | 受力阶段可读，无无意停顿、跳姿或纹理闪烁；慢放只辅助定位 |
| 循环接缝 | 查看末两帧与首两帧、动作方向及按时间归一化的间距 | 位置与运动趋势均能衔接；不能只用末帧长得像首帧判定 |
| 跨状态 | 将每个源逻辑位置与其他目标状态首帧对照；原速抽查最不利切换 | 共同尺度和定位稳定；视角改变、姿势改变与缩放问题分开记录 |
| 合成变体 | 查看复用帧、眨眼合成、无徽标/多个数量及溢出数量徽标 | 没有身体被替换、脸被遮住、轮廓越界或配件跳变 |
| 显示尺寸 | 原生 64 dp 视图及明/暗/棋盘检查底 | 脚掌与表情可读、轮廓干净；放大图好看不能替代小尺寸结果 |

容差来自本次参照和标注误差，记录单位及依据。数值没有充分依据时使用有证据的人工判断并标为人工审查，不能另造通用百分比。艺术判断允许有意夸张，但偏离模型或时间计划的部分须明确写入设计，不能事后解释所有缺陷都属风格。

发现缺陷时按原因处理：比例错误回到模型/源图，跳姿回到相邻动作段，轮廓闪烁检查纹理与降采样，设备独有彩边检查 alpha/解码契约，设备独有卡顿检查播放时序。修复后复查受影响动作段、循环接缝和状态切换；模型、布局或导出器改变则扩大到使用它的全部状态。

## 现有工具能证明什么

| 工具 | 能提供的证据 | 限制 |
| --- | --- | --- |
| `prepare_sprite_frames.py` | 等格几何、禁止放大、透明度正确参与取样、PNG 导出 | 不识别真实格子中的角色，不判断模型尺度、解剖或动作；不会清理旧输出文件 |
| `tests/test_art.py` | 当前生产素材尺寸、格式、序号、回退和特定合成行为 | 不证明所有背景透明、跨状态体量或视觉自然 |
| `tools/audit_animation.py` | 当前生产 PNG 的显示尺寸渲染、联系表、时间表与特定运动指标 | 脚掌坐标读取版本化素材清单；改变图片/帧数后必须重标，当前 PASS 只检查标记采样，范围指标不是通用步态认证 |
| `tools/preview_animation.py` | 默认使用生产逻辑帧映射和曝光时间；`--candidate` 读取显式候选文件/时长清单 | 候选不经过生产合成路径；Ready/保持状态的有限预览也不等同于真实生命周期 |
| `codex-pet test` | 设备上依次触发状态的烟雾检查 | 其他会话会影响显示选择；它不遍历每个来源相位的所有切换，也不证明真实触摸 |

审计工具读取生产路径，没有通用的候选目录或模型校准参数；不能直接跑生产审计后把旧图结果记给新稿。候选阶段查看导出的单帧、联系表和制作单，并以显式清单播放：

```json
{"frames": [
  {"file": "frames/00.png", "seconds": 0.04},
  {"file": "frames/01.png", "seconds": 0.04}
]}
```

文件路径相对该 JSON 文件；条目按曝光顺序排列，不按文件名猜时序。用 `python tools/preview_animation.py --state running --candidate /path/to/frames.json --cycles 2 --output /path/to/candidate.html` 生成独立预览，不替换生产素材。预览器核对 256×256 / 8 bit RGBA、非空帧表和有限正时长；它不做尺寸校准、动作判断或生产徽标合成。进入/保持等非循环片段的预览仅用于有限播放，不证明运行时生命周期。

`audit_animation.py` 默认将 64 dp 按 3× 密度渲染为 192 × 192 位图；现有浏览器预览也用 192 CSS px 容器。浏览器 CSS 像素不自动等于 Android dp，因此该预览用于像素/姿势和时长检查，真实显示大小仍以目标设备为准。

## 接入与验证顺序

1. 候选先通过文件及模型/动作审查。核对工作区，保护无关改动，在 `main` 上更新本次生产素材；不创建新分支。接入前保留当前基线和本次候选，方便只恢复自己的修改。
2. 将物理图片、逻辑帧映射、时长、循环起点和回退图作为一次变更更新。新增外观还需注册正确的图像与动画 profile。Ready 的物理帧不是直接按文件名播放，须检查 `akita_artwork_frame()`。
3. 若更换跑姿或增加帧，重新标注实际脚掌和遮挡并调整受影响审计数据/测试；旧八帧坐标不适用时明确报出，不用旧指标误判。仅修改图片也要检查合成区域是否仍对应眼睛和身体。
4. 运行受影响检查和项目要求的全套测试；生产路径导出当前版本预览/审计。修复失败项后确认相关证据已更新，再在 Termux 设备部署。
5. 按项目流程安装、查询状态并隔离会话演示；查看实际尺寸、循环和状态切换，记录设备/密度、观看结果及日志异常。没有人的设备观察时把视觉项标记 `pending`，不把 GUI ready 等同于已看过动画。
6. 保留已接受的源文件与制作记录，提交并推送本次文件。最终报告说明通过项、遗留缺口和当前素材版本；要求完成的视觉修复尚失败时不能声明已经完成。

集成后的离线检查命令：

```sh
python -m unittest discover -s tests -v
git diff --check
for state in idle running needs_input ready blocked; do
  python tools/audit_animation.py --state "$state" --cycles 2 --density 3 \
    --output "$HOME/.cache/codex-pet/artwork-review/integrated-$state"
  python tools/preview_animation.py --state "$state" --cycles 2 \
    --output "$HOME/.cache/codex-pet/artwork-review/integrated-$state.html"
done
```

记录每条命令的退出状态；部分状态没有针对该动作的模型/步态指标时补人工审查，不解释为自动通过。完整设备流程见[架构文档](architecture.md#verification-by-change-area)，包括 `bash ./install.sh`、`codex-pet status`、隔离会话后的 `codex-pet test` 和日志检查。

## 交付证据

保存一个可追溯版本，包含填写完的制作单、参照图及标注、生成源图、完整提示词与输入引用、帧/时间映射、确定性导出命令、候选和生产帧的对应关系、预览/审计、检查结果和设备验证情况。图片通过后再更新文档中的素材现状；规范文档发布本身不代表全部存量图片已经迁移或重新验收。
