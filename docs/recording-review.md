# 录屏复核与动画迭代

使用 [`tools/review_recording.py`](../tools/review_recording.py) 在本机处理录屏。3 MB 的 MP4 可直接解码；无需先压缩、上传或转换成 GIF。原文件不改动，默认输出到 `~/.cache/codex-pet/recordings/` 的独立目录，不提交录屏和屏幕截图。

## 1. 总览与定位

需要 Python、项目原有 libpng，以及 `ffmpeg` / `ffprobe`。缺少媒体工具时可通过 Termux 的 `pkg install ffmpeg` 安装。脚本仅在媒体子进程中选择 Termux 的运行库，避免 Codex 携带的 C++ 库与 ffmpeg 冲突；不修改 shell 环境或系统库。

```sh
python tools/review_recording.py path/to/recording.mp4
```

打开命令输出的 `index.html`，查看编码宽高、12 个时间位置附近的缩略图和状态切换范围。短视频可能少于 12 张。`manifest.json` 保存源文件名、字节数、SHA-256、视频流、全部原始 PTS、相对时间、每帧时长和工具版本。音频不导出。

## 2. 裁剪宠物并选片段

`--crop x,y,width,height` 使用**编码图像像素**，不采用 Android dp；坐标基于左上角。脚本关闭自动旋转，有旋转元数据的视频仍按总览显示的编码方向定位。更换录屏分辨率或移动宠物后重新定位，不复用旧坐标。

本次录屏的命令：

```sh
python tools/review_recording.py SVID_20261002_075139_1.mp4 \
  --crop 216,392,144,128 \
  --window running:17:18.28 \
  --window stop:23:26
```

- `frames/`：全部原始视频帧的宠物区域，原像素裁剪；不降低采样率、不补帧、不去重。
- `review.html`：完整局部回放，可原速、半速、四分之一速、逐帧或拖动定位；图片解码完成后才启用播放。
- `<片段名>.html`：该时间范围内的样本回放。
- `<片段名>-001.png` 等：每页至多 24 帧的联系表；标注为 `源帧编号/相对毫秒`，精确秒值在 manifest 中。
- `index.html`、`manifest.json`：总览与可追溯的处理记录。

`--window` 可以重复，范围为首个视频帧起算的秒数，按帧时间戳选择 `[start,end)`；不会人为切割跨边界的原始帧。片段名只能含英文字母、数字、下划线或短横线，不能用 `index`、`review`。需要定位变化发生的首帧时，窗口起点应放在变化之前。

可用 `--output /path/to/new-directory` 指定输出；已有目录会被拒绝，避免覆盖上次证据。解码失败不会留下貌似完整的结果目录。输出依赖目录内的相对文件，移动时带上整个目录。浏览器打不开 Termux 私有目录时，把结果目录复制到 Android 可访问的位置后打开；内容仍包含录屏截图，不要发布到公共站点。

## 3. 怎样判断问题

1. **先看原速**：观察完整跑步循环、末帧接首帧、结束后至少 5 秒。
2. **再看逐帧**：记录源帧号/时间；分开跟踪近/远前后脚、头、胸、髋、尾，不靠一张静态图判断步态。
3. **核对状态**：录屏中还在动不等于仍是 Running。Ready 的一次完成动作和随后呼吸应与真正的循环跑步分开记录，必要时对照状态/日志。
4. **区别采样与应用时序**：手机录屏常为可变帧率。静止画面间隔变长、重复画面或某张原画没被录到，不足以证明应用卡顿。总览不能判断步态；不要以固定 `fps=…` 抽帧、重编码或光流插帧后的结果作为时序证据。
5. **浏览器回放也有边界**：页面按保存的 PTS 推进，浏览器仍可能跳过来不及显示的图。逐帧表用于确认录像实际包含什么；它不能重建没被录到的中间动作。

## 4. 固定迭代闭环

每次保留：代码提交、设备上安装的版本、原录屏哈希、处理命令/ROI/时间窗口、观察到的问题与时间点、拟改范围、前后离线对照、自动检查、下次设备录屏结论。图片生成或时序调整仍遵守[素材制作规范](animation-assets.md)，不能把自动测试通过写成视觉验收通过。

先修一个能在录像定位的问题；保留原画与原速对照。部署后以同样的测试步骤录制，重新运行本工具，比较完整周期和结束段。新画稿改变脸型、比例或毛发造成闪烁时，记录失败并保留生产基线，不用帧数或放大补偿掩盖。
