## 复现命令

在仓库根目录运行；目标目录必须不存在，工具不会覆盖已有证据：

```sh
python tools/extract_motion_reference.py \
  SVID_20261002_114154_1.mp4 \
  --output artifacts/akita-running-reference-20261002 \
  --crop 216,396,120,112 \
  --start 20.659744 \
  --end 23.643644 \
  --dedupe-threshold 5 \
  --scale 4
```

`tools/extract_motion_reference.py` 会先用 `ffprobe` 读取逐帧 PTS，再用 `ffmpeg` 固定 ROI 解码；输入录屏只读。若录屏分辨率、宠物位置或状态时间变化，必须重新定位 ROI 和窗口，不能复用这组数字。

## 给生成模型的交接重点

请将透明 `frames/` 作为四肢路径和身体起伏参考，将 MP4 作为节奏参考：

1. 固定秋田犬身份、头脸、胸髋体量、蓝色项圈和侧向镜头；录屏黑底、压缩边缘和裁剪框不是角色设计。
2. 保留清楚的近侧/远侧肢体遮挡，修复当前生产版中近后腿短钩、远前爪下落回抬和后伸后突然回收的问题。
3. 生成时先给出透明 PNG 帧表和每帧时长，再给出视频；首尾至少各带一帧上下文，不能把屏幕录制的采样间隔当成新的动画姿势。
4. 不以“视频看起来更顺”替代四足接触表、固定画布、模型尺度和循环接缝检查。当前生产 Running 仍是原十姿势，未因这份参考自动替换。

## 生成结果回接项目

当前环境没有可直接调用的视频生成模型；这份包是给外部强模型的输入和可审查证据。拿到生成视频后，先保存模型实际输出、提示词、模型/任务标识和 SHA-256，再把它放进独立候选目录。候选处理顺序必须是：

1. 解码生成视频并去除其背景，确认真实 alpha，而不是把白/黑底当透明；记录源 PTS 和帧数。
2. 按 `docs/animation-assets.md` 固定到 256×256 RGBA 画布和当前角色尺度，建立 `pose_id → file → duration_ms` 清单。
3. 按 `docs/animation-motion.md`、`docs/animation-gait.md` 标注两条后腿、两条前腿的可见性、接地与回收路径，逐帧人工看首尾循环和 Running→Ready。
4. 用 `tools/preview_animation.py --candidate` 做离线对照，补齐 `docs/animation-acceptance.md` 要求的哈希、文件检查和设备证据；用户在手机上确认连续奔跑后，才可以把候选复制进生产目录。

不满足上述条件时，保留现有秋田犬生产帧；本参考包不会自动替换它们。
