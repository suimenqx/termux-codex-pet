## 生成过程与拒绝原因

使用内置imagegen，共15次调用；完整提示词、每次输入图片、实际尺寸、SHA与候选取用标记见[generation-inputs.json](generation-inputs.json)。固定模型参照及39张生产PNG快照见[references.json](references.json)。

1. 先生成00后肢承重、02前肢承重。02初稿把前脚都伸到前方，进行了定向修订。
2. 扩展其余六姿势。文字中的脚掌坐标没有稳定落实，01、04、06、07再修订。
3. 06、07补充四肢位置示意图后再次生成。示意图是代码绘制的技术参考，不是生产图片；原生生成稿仍未可靠遵循落点，并发生头部/构图变化。这两张guided稿拒绝选入候选。
4. 八张候选保留修订前后的可复查状态，使用`export-draft.json`保护原头脸与项圈。但这只能保护身份，不能修复生成稿的动作错误。

不得把“输入了姿势图”“符合256px”或“像素保护测试通过”当作正确步态证据。本次说明当前逐张生成方式对精确肢体路径的控制仍不可靠；继续制作须先把05→06→07的后肢接地/回收三姿势校准成功，再扩展整圈，不能重复先批量出图再补救。

## 复现

在仓库根目录执行，导出目录必须尚不存在：

```sh
python tools/prepare_motion_repairs.py docs/artwork/akita/2026-10-rhythm/export-draft.json /path/to/new-export
python docs/artwork/akita/2026-10-rhythm/build_review.py
python tools/preview_animation.py --state running --candidate docs/artwork/akita/2026-10-rhythm/candidate.json --cycles 2 --output /path/to/candidate.html
```

`build_review.py`读取本包冻结的前后图片、顺序和时长，不调用当前生产帧映射来推断历史动画。`review/spacing.json`是固定画布坐标下的位移/曝光，包含循环接缝；生产审计的`transitions`使用相对髋部坐标，两者不能混为同一测量。遮挡段不补造速度。

八张导出图均为256×256 RGBA；外边缘保留原图的1/255 alpha像素，严格全零边缘检查未通过，见[文件检查](review/file-check.json)。这些微弱像素位于锁定区域之外；本轮保留证据，没有顺便修改生产图。

检查记录见[validation.json](validation.json)。自动检查用于证明资料可复现、图片边界与播放数据可追溯，**本包的动作验收结论仍是未通过**。
