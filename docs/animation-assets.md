# 秋田犬动画图片规范

本文是秋田犬所有状态动画图片的统一检查与制作规范。代码中的逻辑帧顺序和时长以 [`codex_pet/animation.py`](../codex_pet/animation.py) 为准；帧图由 [`codex_pet/art.py`](../codex_pet/art.py) 加载。经典机器人由代码绘制，不属于本图片规范。

## 本轮全状态审视

秋田犬共使用 29 张独立帧图，文件都位于 `codex_pet/assets/akita/frames/`。Ready 有 13 个逻辑播放帧，但会复用 Idle 和运行时合成的眨眼，所以它只需要 5 张独立 Ready 帧图。所有帧都使用 256 × 256 透明 PNG，并放进同一个 64 dp `ImageView`；3× 密度审计预览为 192 × 192 像素。

下表的可见面积按 alpha > 128 的像素数除以 256 × 256 画布像素数计算。数据来自 `rgba_icon()` 的生产帧输出，覆盖每个状态的所有逻辑播放帧。

| 状态 | 独立帧图 / 逻辑帧 | 可见面积范围 | 全状态审视 |
| --- | ---: | ---: | --- |
| Idle | 8 / 8 | 44.97–46.29% | 站立呼吸、眨眼和摆尾；身体锚点稳定。 |
| Running | 8 / 8 | 39.74–41.99% | 侧向不对称疾驰；相对 Idle 第 0 帧为 87.54–92.49%，四只脚的轨迹已单独审计。 |
| Needs input | 4 / 4 | 43.45–45.51% | 抬爪挥动，轮廓尺寸与站立状态接近。 |
| Ready | 5 / 13 | 35.14–46.29% | 先蹲身、跃起，再回到 Idle 姿势呼吸；进入动作与站立循环的面积变化是姿势变化。 |
| Blocked | 4 / 4 | 34.38–36.49% | 坐姿歪头并停留；占地面积较小来自收腿坐姿，不是视图或画布缩放变化。 |

这轮还发现各状态的观察角度和项圈颜色并非完全一致：Running 更侧向，部分其他状态更正面或呈三分之四侧面，项圈颜色也随状态变化。现有素材的脸部和毛色仍可识别为同一角色；以后新生成或整组重绘时，应固定观察角度、项圈和主要配色，只改变动作与表情。当前尺寸规范不要求拉伸坐姿或腾空姿势去匹配站立轮廓面积。

此前 Idle、Needs input、Ready、Blocked 的根目录单帧回退图比动画首帧大。本轮已把它们同步为各自 `frames/<state>/00.png` 的逐字节副本；Running 回退图原本已同步。即使运行时回退到单帧，也不会因加载另一张旧大图而突然改变大小。

## 生成和导出规范

### 角色与构图

- 所有状态沿用同一角色设定：头身比例、眼鼻嘴、毛色分区、耳朵、尾巴、项圈、描边和光照方向保持一致。变化来自姿势、表情和状态提示色，不要让每一帧像重新设计了角色。
- 锁定镜头、朝向和透视。不同动画可以因动作需要改变身体方向，但需要在动作序列内保持连贯；跨状态也应保留可识别的面部和身体比例。
- 使用图像生成模型时，把各关键姿势作为同一角色、同一镜头下的源素材，并说明透明正方形画布和共同锚点。模型输出只能视为源图：提示词不能保证像素级画布、占比、落点或网格对齐；导出前仍须逐帧裁切、配准、缩放和检查。
- 以胸口和髋部等躯干锚点配准各帧。不要按每帧的 alpha 外接框自动居中，否则伸展的爪子、尾巴或耳朵会带着身体横向跳动。
- 四肢和尾巴必须完整留在画布内。运行帧要标明近侧与远侧肢体，避免两条腿始终重叠成一条。

### 源图和输出尺寸

- 生成单帧源图时使用正方形透明画布；建议每帧至少 512 × 512，生成工具允许时优先 1024 × 1024，再以确定性的离线流程缩到运行尺寸。
- 生成动作表时使用等大的正方形格子，每格至少 512 × 512；画布尺寸必须严格等于列数和行数乘以格子尺寸。不要在格子间加入标题、边框或不等宽留白。若生成器不能准确遵守网格，应先逐格定位并核对，再导出，不能直接把整张图当成动画帧。
- 当前生产帧的唯一尺寸是 **256 × 256 像素、RGBA、透明背景 PNG**。PNG 使用直通道 alpha；Android 的 PNG 解码器负责绘制前的 alpha 预乘。不要用 JPEG，也不要把原始直通道 RGBA 直接复制到 Termux:GUI 的共享位图缓冲区。
- 所有状态在相同的 64 dp 视图里播放，不对单个状态在运行时额外缩放。用透明留白、统一的导出缩放和锚点配准控制角色在画布中的占比。

### 尺寸验收阈值

- 对最终 256 × 256 帧，以 alpha > 128 作为可见轮廓，面积应在画布的 **32–48%**；四边到可见轮廓至少留 **4 px**。此范围覆盖当前所有姿势，并防止意外生成太小、裁切或贴边的帧。
- Running 每帧的可见面积应在 Idle 第 0 帧的 **78–95%**。当前实测为 87.54–92.49%。
- 坐下、蜷缩、下蹲或伸展等有意的姿势变化允许改变面积；审核要同时看完整帧、姿势连续性和 64 dp 生产尺寸预览。若视觉上突然变大或缩小，先调整源图在画布中的统一比例和锚点，再重导帧图，不要靠 GUI 状态切换时缩放。

## 帧文件与回退图

- 文件使用 `frames/<state>/<index>.png`，编号从 `00.png` 连续递增，不能留空号。当前独立帧数量为 Idle 8、Running 8、Needs input 4、Ready 5、Blocked 4。
- `animation.py` 管理每个状态的逻辑帧数、姿势映射、循环/停留规则和时长。Ready 的第 6 个逻辑位置开始复用 Idle 和眨眼，不要为这些已复用姿势复制新图。
- 根目录 `codex_pet/assets/akita/<state>.png` 是对应动画目录 `frames/<state>/00.png` 的单帧回退图，两者必须逐字节相同。更新首帧时同时同步回退图。
- 运行帧表的当前来源是 [`docs/artwork/running-gait-sheet.png`](artwork/running-gait-sheet.png)。用 [`tools/prepare_running_frames.py`](../tools/prepare_running_frames.py) 按 4 × 2 网格逐格缩放，并生成 8 张 256 × 256 帧。现有动作表每格约 443.5 × 443.5 px，是采用专用导出参数并通过尺寸与步态审计的存量素材；新生成动作表按每格至少 512 × 512 px 制作。`RUNNING_ART_SCALE = 1.18` 是针对这张源表的经验校准：同一导出流程用 1.0 时，可见面积为画布的 28.53–30.16%，即 Idle 第 0 帧的 62.85–66.43%；居中放大 1.18 倍后，面积变为 39.74–41.99%，即 Idle 第 0 帧的 87.54–92.49%。它不是图像生成参数或其他状态的通用比例。换用新的源表时要重新测量并审计缩放值；当前工具还对这张动作表应用下排 10 px 配准偏移。

## 审计与验收

逐状态生成与生产路径一致的预览、联系表和逐帧报告：

```sh
for state in idle running needs_input ready blocked; do
  python tools/audit_animation.py --state "$state" --cycles 2 --density 3 \
    --output "$HOME/.cache/codex-pet/asset-review-$state"
done
```

在 192 × 192 的预览下检查轮廓面积变化、帧间跳动、循环接缝、透明边缘和角色辨识度；奔跑状态还要看四只脚的相对轨迹。需要验证完整生产帧表时运行：

```sh
python -m unittest discover -s tests -p 'test_art.py' -v
```

这些测试检查 PNG 尺寸、全状态轮廓面积和边距、Running 相对尺寸，以及每个状态回退图与首帧的一致性。GUI 素材改动还需按 [架构文档的验证流程](architecture.md#verification-by-change-area) 安装到设备并检查实际显示；离线审计不能代替设备上的实时观感检查。
