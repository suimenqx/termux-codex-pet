# 秋田犬动画图片规范

本文定义秋田犬动画素材的制作、导出和审查契约。它以生产显示尺寸、角色模型参照、动作连续性和可复现的像素处理为依据，不以跨姿势轮廓面积相等作为目标。逻辑帧顺序与时长以 [`codex_pet/animation.py`](../codex_pet/animation.py) 为准；素材加载与合成以 [`codex_pet/art.py`](../codex_pet/art.py) 为准。经典机器人由代码绘制，不属于本规范。

## 当前素材审视

秋田犬有 29 张独立帧图，位于 `codex_pet/assets/akita/frames/`。Ready 有 13 个逻辑播放位置，但会复用 Idle 图并在运行时合成眨眼，因此只需要 5 张独立 Ready 帧。各状态共享 256 × 256 RGBA PNG 画布，并显示在同一个 64 dp `ImageView` 中。

| 状态 | 独立图 / 逻辑位置 | 当前动作与审查要点 |
| --- | ---: | --- |
| Idle | 8 / 8 | 站立呼吸、眨眼、摆尾；躯干锚点稳定。 |
| Running | 8 / 8 | 侧向不对称疾驰；近、远侧四只脚分别审查，循环接缝单独检查。 |
| Needs input | 4 / 4 | 抬爪挥动；手势在 64 dp 显示尺寸下仍可读。 |
| Ready | 5 / 13 | 蹲身、轻跃后回到站立呼吸；跃起是进入动作，不在稳态循环中反复播放。 |
| Blocked | 4 / 4 | 坐姿歪头并停留；坐姿收腿造成的轮廓变化属于姿势本身。 |

奔跑使用侧面视角，其他状态以更正面或三分之四侧面表达表情和手势。这些视角差异可以保留，但每个动作序列内部必须保持镜头、透视与角色模型一致。项圈颜色可以承担状态提示；每种颜色应是有意的状态映射，而非逐帧漂移。脸部结构、毛色分区、耳朵、尾巴、项圈形状、描边和光照方式共同定义角色身份。

此前单帧回退图与动画首帧曾出现版本不一致，现已统一为逐字节相同。运行时切到回退图时不会因此加载另一套构图。

## 角色模型与构图规范

- 先维护一组固定的角色参照图，再绘制新帧。至少覆盖该动作会用到的视角；当前正面/三分之四侧面可参照 `frames/idle/00.png`，侧面可参照 `frames/running/00.png`。新姿势用同视角参照，不能只靠文字重复描述角色。
- 参照头骨宽度与躯干长度、眼距与口鼻比例、耳朵和尾巴形状、毛色边界、项圈形状及明暗关系。它们比整张轮廓面积更能识别模型是否被重新设计或意外缩放。
- 一个动作序列固定视角、投影、角色空间尺度与绘制风格。跨动作允许为表达动作切换视角，但需要能与相应视角的角色参照对应。
- 为每个序列指定稳定的角色根锚点，例如站立序列的躯干/脚底关系、奔跑序列的髋部中心。脚掌支撑、身体起伏和腾空要围绕这个锚点形成有意的动作；禁止逐帧自动按透明外接框重新居中或单独缩放。
- 四肢、耳朵和尾巴应完整留在格内。运行帧须能区分近侧与远侧肢体；接触、蹬地、腾空和回收这些阶段要在小尺寸下读得出来。
- 蹲坐、腾空、挥爪等姿势可以改变可见轮廓面积。不得用面积百分比把这些动作拉成同样轮廓；如果同一角色在一致的参照姿势下显得忽大忽小，应回到源图修正角色模型尺度或重绘素材。

## 像素与动作表契约

- 生产素材必须是 **256 × 256、RGBA、透明背景 PNG**。应用以一个 64 dp 视图显示所有状态；不要按状态在 GUI 中另行缩放。
- 源图只能保持或高于生产像素分辨率，最终缩到 256 × 256；禁止把较小帧放大充当高清源图。图像生成服务可能不遵守提示词中的确切像素尺寸，必须检查生成文件本身的 IHDR 信息。
- 动作表应由等大正方形格子组成，无标题、边框、沟槽或跨格装饰。格子按从左到右、从上到下排列。整张表不必让宽高整除列数/行数，但必须满足相同的正方形格子几何；导出器会验证此条件并按比例切格，因此像 1774 × 887 的 4 × 2 表也能准确表示等大的半像素边界格子。
- 如果生成图的格线、留白或角色跨格导致格子无法确定，不能猜测切点后接入生产素材；应修正/重做源图，或先以可复查方式明确每个格子的真实边界。
- 新素材使用 [`tools/prepare_sprite_frames.py`](../tools/prepare_sprite_frames.py) 做行优先裁格，并以双线性、预乘 alpha 采样缩到生产尺寸。工具不放大、不移动角色，也不加逐帧比例补偿。示例：

  ```sh
  python tools/prepare_sprite_frames.py source-sheet.png /tmp/akita-running \
    --columns 4 --rows 2 --frame-count 8
  ```

- PNG 存储直通道 alpha。显示端通过 PNG 解码预乘 alpha；不能将 `rgba_icon()` 的原始 RGBA 字节直接写入 Termux:GUI 的共享位图缓冲区。
- 对生成式绘图，提示词应引用同一套角色参照和对应视角，描述每格唯一姿势、动作阶段、近远侧肢体和共同根锚点。生成结果是待审查的源稿，不是可直接发布的帧图；实际尺寸、网格和解剖结构以生成文件和逐帧检查为准。

## 1.18 的历史来源（仅用于复现旧素材）

`1.18` 来自提交 `f1cafd9`（“Match running artwork footprint to other pet states”）。当时发现现有奔跑源表的角色在固定 64 dp 视图中显得偏小，于是在旧导出脚本中对整组跑姿作了居中放大。对同一张旧源表，倍率 1.0 导出后的 alpha 可见面积是画布的 28.53–30.16%；当时的 1.18 输出是 39.74–41.99%。这是对那张源图做过的历史性补偿，不是图像生成参数、专业通用比例或新素材验收标准。

当前 [`tools/prepare_running_frames.py`](../tools/prepare_running_frames.py) 和下排 10 px 配准值只保留为旧源表的确定性重建器，以便逐字节复现已提交帧图。新帧表必须使用通用导出器，不得继承这些源图专属参数。如果后续重绘跑姿，应让源图从角色模型参照阶段就具备正确尺度和根锚点，通过完整审查后替换旧素材，并同步 `running.png` 回退图。

## 审核门槛

接入前逐状态查看生产帧联系表，并以实际 64 dp 大小播放至少两个周期。自动检查与人工审查分别负责不同问题：

1. **文件完整性：** PNG 解码成功、像素尺寸和颜色类型符合生产契约；编号从 `00.png` 连续递增；独立帧数与逻辑映射相符；每个状态的回退 PNG 与首帧逐字节相同。
2. **模型一致性：** 对照相同视角的模型参照，检查头部与躯干比例、脸部特征、毛色分区、配件、描边和光照。检查不是比较不同姿势的总体 alpha 面积。
3. **构图与注册：** 检查身体锚点是否稳定、是否意外缩放或漂移、四肢是否完整、有无格线/邻帧串入。腾空造成的整体起伏必须属于设计好的动作路径。
4. **动作可读性：** 查看完整循环及首尾接缝。奔跑须单独核对四只脚的轨迹、支撑和腾空阶段、近远侧遮挡及相位差；复用 `tools/audit_animation.py` 的脚掌标记前，先确认标记仍落在新素材的对应脚掌上。
5. **小尺寸观感：** 在 64 dp 预览中确认表情、状态手势、脚掌和尾巴仍可辨认；如出现不自然跳动或体量变化，修正源图和注册关系后重新导出，不添加只作用于单一状态的 GUI 缩放值。

审计命令：

```sh
for state in idle running needs_input ready blocked; do
  python tools/audit_animation.py --state "$state" --cycles 2 --density 3 \
    --output "$HOME/.cache/codex-pet/asset-review-$state"
done
```

预览图模拟生产帧经过 `rgba_icon()` 和 64 dp 视图缩放的像素，不能替代 Android/Termux:GUI 设备检查。更新 GUI 可见素材后，按[架构文档的验证流程](architecture.md#verification-by-change-area)在设备上安装、运行状态检查并查看实际显示。
