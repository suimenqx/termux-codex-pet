# 宠物图片与动画制作规范

本文件是 agent 制作宠物素材的入口。目标是让同一角色在换状态、补帧和重新生成后保持可识别的体量、稳定的构图与连续的动作。规范覆盖生成、重绘、补帧、导出和接入；当前实例是秋田犬 PNG 帧。经典机器人的图像由代码绘制，沿用其自身的像素尺寸和动画配置。

## 数字的来源

每个尺寸、坐标、时长或容差都要归入下面一种来源，并在制作单注明。没有依据时保留待测，不把当前素材的最大/最小值反推成新规范。

| 类型 | 来源及用途 |
| --- | --- |
| 运行契约 | 从代码读取，例如图片像素尺寸、视图 dp、逻辑帧映射和逐帧时长。 |
| 模型设定 | 来自带版本的角色模型参照，例如中性姿势头部尺度、配色和共同构图。属于本角色的设计选择。 |
| 计算值 | 由契约计算，例如像素到 dp 的换算、一个周期的总时长。记录公式和输入。 |
| 测量及容差 | 记录测量点、视角、单位、标注误差、比较对象及显示尺寸证据。未确定容差的项目需要人工审查。 |

本项目不规定所有角色共用的面积占比、头身比、帧率或缩放补偿系数。姿势、视角与动作节奏不同，不能用同一轮廓面积证明大小一致，也不能用帧数证明流畅。

## 角色模型与尺寸

### 固定模型参照

一个角色版本至少包含：身份主图；该动作涉及的中性姿势视图；头脸、毛色、配件和光照说明；同尺度的视图对照；标注过的构图图。多视图在共同尺度、相容的投影与镜头高度下制作，并在批量画动作前审查。当前造型的参照链接见文末。

分别声明参考图的用途：`identity`（角色身份）、`scale`（尺度）、`pose`（姿势）、`layout`（构图）。一张旧跑姿可以提供动作信息，但不会自动成为新角色的尺寸标准。后续生成始终携带固定模型参照；相邻帧只补充动作信息，避免连续以新稿替代模型参照而逐渐变形。

统一尺寸关系和构图应在角色设计阶段完成，并交给后续制作者使用；这是本项目采用模型参照与同尺度对照的依据。[Toon Boom：Size Relation](https://docs.toonboom.com/help/game-studio-24/game-asset-editor/rigging/about-size-relation.html)

### 三种尺寸和两类锚点

| 名称 | 定义 | 怎样锁定 |
| --- | --- | --- |
| 画布尺寸 | 整张透明 PNG 的宽高 | 由外观注册和渲染契约决定 |
| 角色尺度 | 同一模型在固定投影下的大小 | 同视角、中性姿势的模型测量与共同镜头；不随状态独立调整 |
| 姿势轮廓 | 耳、尾、四肢等在当前动作中的投影范围 | 允许随动作变化，但完整落在画布内 |
| 构图原点 `O` | 每张帧图共同的定位坐标，供比较帧间位置使用 | 在参考构图中选定并记录，跨帧固定；当前 PNG 不携带运行时 pivot 元数据 |
| 动作标记 `p(t)` | 头、胸、髋、脚掌、尾根等随动作移动的点 | 在姿势表中记录轨迹和可见性；髋部起伏不等于构图原点漂移 |

制作单使用连续画布坐标：左上边界为 `(0, 0)`，向右、向下为正。画布边长为 `C`，归一化坐标为 `u=x/C, v=y/C`；标注栅格像素 `(i,j)` 时取其中心 `(i+0.5,j+0.5)`。源图与导出图使用同一归一化构图。

当前秋田犬 `C=256 px`、视图 `V=64 dp`，所以图中长度 `l` 的显示长度是 `l × V/C` dp，在密度 `d` 下是 `l × V/C × d` 屏幕像素。换分辨率时使用这个映射；容差注明是在源图、生产图、dp 还是屏幕像素中测量。

### 建立尺寸基准的步骤

1. 选择身份主图并建立动作所需的中性视图。把参考版本和文件哈希记录下来。完成条件：所有视图能对应到同一个角色，投影和姿态说明齐全。
2. 在同视角中标注可重复定位的结构点，例如头骨上下边界、眼/鼻位置、胸与髋；记录对应距离与比例。毛尖、耳尖、摆动尾巴和张开的嘴不作为固定尺度尺。头部旋转或遮挡时使用对应视角参照，不能强行比较投影宽度。完成条件：标记图、坐标、测量方法和不确定性可复查。
3. 在同一画布摆出站立、坐姿、下蹲、最大伸展和最高腾空等计划极值，确定共同构图原点、支撑基线和动作范围。检查数量徽标等运行时叠加是否遮住脸或关键动作。完成条件：全部极值在共同布局中完整可读。
4. 锁定这个版本的尺度和布局，再制作完整动作。发现空间不足时回到极值布局统一修正；不能只缩小伸展帧或单一状态来塞进画布。完成条件：源图通过模型/构图审查后才进入批量生成。

身体压缩、伸展和透视变化写入动作设计，保护角色体积感和头脸身份。自动按每帧透明外接框居中、按面积等比补大小会破坏上述基准，应保持整张画布的映射。

## 源图与导出契约

生产数据以 [`pets.py`](../codex_pet/pets.py)、[`art.py`](../codex_pet/art.py)、[`animation.py`](../codex_pet/animation.py) 和 [`gui.py`](../codex_pet/gui.py) 为准。当前秋田犬交付 **256 × 256、8 bit/通道 RGBA、透明背景的独立 PNG 帧**，共享同一 64 dp 视图。新外观先确定自己的注册尺寸和渲染路径。

- 生成前填写目标源图尺寸及网格。单格源分辨率至少等于生产分辨率；更高分辨率服务于绘制细节，不能保证模型比例或动画质量。若采用整数倍工作画布，记录该倍数的工具/制作依据，不把它设成所有素材的质量阈值。
- 动作表的格子等大、正方形、无沟槽或边框，按行从左到右排列。实际宽高 `W,H` 与列行数 `c,r` 满足 `W×r = H×c`。生成文件的真实尺寸为准；几何满足时，导出器支持半像素等非整数格界。
- 文件宽高满足比例只证明可以按等格取样，不能证明生成器真的把角色放进了这些格子。逐格查看跨格肢体、标题、边框和不均匀留白；版式错误先修源图，必要时改成逐帧生成。
- 留白由动作极值、取样边缘和叠加区域决定并记录，不能只用任意固定边距证明不会裁切。背景须为真实 alpha 透明；棋盘格是审查背景，不是图像内容。
- 当前通用导出器 [`prepare_sprite_frames.py`](../tools/prepare_sprite_frames.py) 做等格裁切和预乘 alpha 双线性采样，不提供自动角色配准、模型校准或绘画质量判断。它禁止低分辨率放大，也不提供额外角色缩放或偏移参数。高倍率缩小时仍要审查细线、毛发和边缘的闪烁/混叠。
- 该导出器的 CLI 当前输出 `AKITA_SIZE`，即 256 px；新外观采用其他生产尺寸时须适配导出调用并核对渲染契约，不能只改制作单中的尺寸字段。
- 全套素材采用一致的色彩解释；源稿工作空间记录在制作单中，默认制作目标为 sRGB。当前导出 PNG 不保留源稿的全部色彩元数据，带不同配置文件的素材须核对导出颜色，不能把删掉配置文件当作颜色转换。
- PNG 保存直通道 alpha；取样时预乘、写回 PNG 时还原直通道，显示端通过 PNG 解码完成合成。该 alpha 表示由 [W3C PNG §6.2](https://www.w3.org/TR/png-3/#6AlphaRepresentation) 定义。原始 `rgba_icon()` 字节不直接写入 Termux:GUI 的预乘共享位图。

物理图片编号使用 `frames/<state>/00.png` 起的连续序列；播放位置与物理文件分开管理，Ready 等动作会重排、复用和合成图片。每个状态根目录回退图等于对应物理 `00.png` 的逐字节副本。接入方法见[验收与接入](animation-acceptance.md)。
